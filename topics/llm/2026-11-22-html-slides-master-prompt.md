## TL;DR — 5줄 요약

1. **발표자료를 "슬라이드 파일"이 아니라 "웹페이지"로 만든다.** HTML 슬라이드는 ①어디서 열어도 폰트가 안 깨지고 ②숫자·그래프가 마우스에 반응하며 ③글자를 화면에서 직접 고칠 수 있고 ④AI가 코드로 만든 모션그래픽을 그대로 넣을 수 있다.
2. **도구는 챗지피티(Work) 또는 클로드 데스크톱 앱 하나면 된다.** 둘 다 "폴더를 프로젝트에 연결"해 두면 그 폴더의 자료·디자인 레퍼런스를 읽고 결과물을 같은 폴더에 저장한다. 프롬프트는 완전히 동일하다.
3. **작업은 초안 → 수정 → 모션그래픽 3단계다.** 초안은 마스터 프롬프트 한 번(주제·분량·폰트 3칸만 채움), 수정은 "몇 페이지를 어떻게" 한 줄씩, 모션은 레퍼런스 영상을 폴더에 넣고 "이거 참고해서 15초로" 한 줄.
4. **차별화는 효과 3종과 편집 모드에서 나온다.** 채우기(호버), 연동(레버·연도), 사이드 페이지(클릭 시 상세), 그리고 클릭/엔터로 요소 순차 등장. 전부 프롬프트 한 줄로 붙는다.
5. **만능은 아니다.** 공공기관·일부 기업은 PDF/PPT만 받고, 효과를 다 넣는 게 목적이 아니다. 발표자료의 본질은 청중과의 소통이므로 **상황에 맞게 골라 쓰는 능력**이 도구를 아는 것보다 중요하다고 영상은 말한다.

## 1. 왜 HTML 슬라이드인가 (0:00)

**영상이 드는 장면:** 숫자와 그래프가 마우스에 자연스럽게 반응하고, 내용을 누르면 세부 정보가 원하는 위치에서 등장한다. 클릭한 연도에 맞춰 화면 안 수치만 자동으로 바뀌고, 레버를 움직이면 관련 내용이 따라온다. 글자는 슬라이드 안에서 바로 수정되고, 모션그래픽도 그 자리에서 만들어 붙인다. 폰트가 깨질 걱정 없이 어디서든 열린다.

**왜 지금인가:** 발표뿐 아니라 클라이언트 미팅, 고객 견적 상담처럼 "한 화면에서 조건을 바꿔 보여줘야 하는" 자리가 많은데, 정적 장표는 그때마다 화면을 넘겨야 한다. 영상은 이 네 가지(폰트·반응형 수치·인라인 편집·모션)를 HTML로 한 번에 얻는다고 정리한다.

**완료 기준:** 내 발표에서 "화면을 넘겨야만 설명되던 장면"을 하나 이상 떠올릴 수 있다. 그 장면이 이 방식의 후보가 된다.
**한 줄 정리:** HTML 슬라이드는 예쁜 PPT가 아니라, **조건을 바꿔 보여주는 발표 도구**다.

## 2. 필수 세팅 — 폴더·레퍼런스·두 앱 (1:30)

**영상이 시키는 딱 세 가지:**

1. **PC에 작업 폴더를 만들고 발표 자료를 넣는다.** PDF·Word는 물론 Excel도 된다. 파일 하나 또는 여러 개 모두 가능.
2. **회사 템플릿이나 디자인 레퍼런스를 같은 폴더에 넣는다.** 영상은 핀터레스트에서 "PPT"로 검색해 마음에 드는 이미지를 받아 넣고, **파일명을 `디자인 레퍼런스`로 바꾸라**고 한다. 이름을 고정해야 프롬프트에서 그 파일을 지목할 수 있다.
3. **챗지피티와 클로드 데스크톱 앱을 설치하고, 각각 그 폴더를 프로젝트에 연결한다.**

| | 챗지피티 | 클로드 |
| --- | --- | --- |
| 앱 | ChatGPT 데스크톱 앱 → 상단 **Work** | Claude 데스크톱 앱 |
| 모델 | 최신 모델(자막 "6.1 쏘"), 추론 수준 **High** | **Opus 5.5**, 노력 수준 **높음** |
| 폴더 연결 | 프로젝트 선택 → **새 프로젝트** → 폴더 추가 → 폴더 선택 | 프로젝트/폴더 → **폴더 추가** → 폴더 선택 |
| 추가 설정 | **플러그인**에서 Sites 활성화 (프롬프트 맨 앞 `@Sites`) | 없음 |

**왜 폴더 연결이 핵심인가:** 두 에이전트가 폴더 안 자료를 읽어 슬라이드를 만들고, **결과물(HTML)을 같은 폴더에 자동 저장**한다. 그래서 나중에 파일을 찾으러 다닐 필요가 없고, 레퍼런스 이름만 바꿔 프롬프트에서 지목할 수 있다.

**완료 기준:** 두 앱의 채팅창에서 "이 폴더에 어떤 파일이 있냐"고 물었을 때 파일 목록이 나온다.
**한 줄 정리:** 세팅의 본질은 모델 고르기가 아니라 **"자료 + 디자인 레퍼런스 + 출력 폴더"를 한 폴더로 묶는 것**이다.

## 3. 1단계 초안 — 마스터 프롬프트 (3:25)

**영상의 프롬프트 사용법:** 설명란/고정 댓글의 마스터 프롬프트를 복사해 붙여넣고, **괄호 세 곳만** 채운다.

| 채울 칸 | 영상의 예시 | 실무 요령 |
| --- | --- | --- |
| `[주제]` | 테슬라의 사업 현황과 계획, 새로 나온 로드스터 | 맥락을 길게 쓸수록 결과가 맞아진다(영상 강조) |
| `[7장]` | 5~10장 권장 | 뒤에서 장표 추가·사이드 페이지로 늘릴 수 있으니 **짧게 시작** |
| `[눈누 폰트 주소]` | 눈누 폰트 페이지 URL | 폰트만 깔끔해도 퀄리티가 크게 오른다(영상 강조) |

**폰트 고르는 법(4:16):** 눈누 → 무료 폰트 → 허용 범위 **OFL** 필터 → 마음에 드는 폰트 클릭 → **폰트 페이지 주소 복사** → 프롬프트에 붙여넣기.

**영상이 프롬프트에 직접 넣어 둔 지시 4개**(결과 품질을 가르는 부분이라 그대로 두는 게 좋다):
- 디자인은 폴더의 `디자인 레퍼런스`를 활용
- 줄바꿈은 **단어 단위**로 → 한글이 단어 중간에서 끊기지 않게
- **마우스에 반응하는** 슬라이드를 HTML로
- 수치 장은 **chart.js 샘플에서 데이터에 맞는 차트를 골라** 넣기

**완료 기준:** 엔터 후 HTML 파일 하나가 폴더에 생기고, 브라우저에서 열어 페이지를 넘길 수 있다.
**한 줄 정리:** 초안 단계에서 욕심내지 말고 **5~10장 + 폰트 + 레퍼런스**만 정확히 준다.

## 4. 2단계 수정 — 내용 → 편집 모드 → 효과 (4:54)

영상은 수정을 **내용 수정**과 **효과 추가**로 나눈다. 순서가 중요하다: 장표 전체 구성과 문구를 먼저 다듬고, 그 다음 효과를 얹는다.

### 4-1. 내용 수정 (5:09)
- **전체를 먼저 보고 개별 문구를 고친다.** 텍스트가 크거나 작으면 "전체 텍스트를 지금보다 조금 더 키워줘" 한 줄.
- 장표 추가는 **어느 페이지 사이에 무엇을** 넣을지 지정한다: "2페이지와 3페이지 사이에 최근 3년 동안의 매출과 차량 생산 개수를 조사해서 추가해줘." 조사까지 시키는 게 포인트다.
- 삭제·순서 변경도 페이지 번호로 지정한다.

### 4-2. 편집 모드 (5:59)
- "글자를 직접 클릭해서 수정할 수 있는 편집 모드를 넣어줘" → 화면에 **편집 버튼**이 생기고, 클릭해서 바로 고친다.
- 수정 후 **저장 → 편집 완료**를 누르고, **반드시 "앞서 설정한 편집 모드를 해제해줘. 수정한 텍스트는 모두 그대로 저장해줘"**로 끈다. 안 끄면 발표 중에 실수로 글자가 바뀐다.

### 4-3. 효과 3종 (6:50~8:36)

| 효과 | 요청 한 줄의 구조 | 쓰는 자리 |
| --- | --- | --- |
| **채우기** | "숫자랑 그래프에 마우스를 대면 자동으로 채워지는 효과를 추가해줘" | 기업 성과·재무 수치 강조 |
| **연동(레버)** | "N페이지의 A·B·C 옵션에 대해, 이미지 오른쪽 세로 레버를 움직이면 관련 내용·이미지가 연동돼 나오게" | 제품 사양 비교 |
| **연동(연도)** | "N페이지의 2023·2024·2025를 누르면 매출·생산량과 주요 재무 수치가 연동돼 그래프로 나오게" | 실적 추이, 견적 상담 |
| **사이드 페이지** | "N페이지 아래 항목을 누르면 아래에서 사이드바가 올라와 세부 내용을 보여줘. 주변은 어둡게, 흐림 효과는 넣지 말아줘" | 사업 목록 → 상세 설명 |

**영상이 짚는 원칙:** 효과를 낼 때는 **"어느 페이지에서 / 무엇을 선택하면 / 무엇이 어떻게 바뀌는지"** 세 가지를 적는다. 이 세 개가 없으면 AI가 임의로 해석한다.

**사이드 페이지를 쓰는 이유:** 파워포인트에서는 사업별 상세를 보여주려면 화면이 통째로 바뀌어 청중이 큰 그림을 잃는다. HTML은 한 화면 위에 상세가 겹쳐 올라오므로 **전체 구조 안에서 세부를 설명**할 수 있다. 그래서 영상은 **모든 장표를 한 번에 만들지 말고 주요 챕터별로 만든 뒤 사이드 페이지로 붙이라**고 권한다.

**완료 기준:** 발표 중 마우스로 수치가 바뀌고, 상세가 한 화면에서 열린다. 편집 모드 버튼은 화면에 없다.
**한 줄 정리:** 수정은 **구성 → 문구 → 효과** 순서, 효과는 **페이지·트리거·결과** 3요소로 지시한다.

## 5. 클릭 진행·자동 발표 (9:44)

- "각 장표별로 빈 화면에서 시작하고, 마우스를 클릭하거나 엔터를 칠 때마다 요소들이 순서대로 나오게 변경해줘" — 파워포인트의 애니메이션과 같은 리듬.
- "'발표 시작하기'를 누르면 자동 발표가 진행되도록 바꿔줘" — 전시·키오스크형.
- 영상의 경고: **효과를 전부 쓸 필요는 없다.** 원고와 상황에 맞는 것만 고른다.

**완료 기준:** 발표 리허설을 실제 진행 방식(클릭/자동)으로 한 번 돌려본다.
**한 줄 정리:** 진행 방식까지 프롬프트로 정해 두면 리허설과 실연이 같아진다.

## 6. 3단계 모션그래픽 (10:21)

**정의:** 모션그래픽은 **AI가 코드로 만드는 동영상**이다. 글자와 그래픽이 역동적으로 움직인다.

**가장 쉬운 방법은 레퍼런스다.** 좋은 모션 영상을 보여주고 "이거 참고해서"라고 하는 것.
1. 모션그래픽 레퍼런스 사이트에서 마음에 드는 것을 다운로드
2. 작업 폴더에 저장하고 파일명을 **`모션그래픽 레퍼런스`**로 변경
3. 채팅창에 요청: **"폴더 속 '모션그래픽 레퍼런스' 영상을 참고해서 [주제] 15초 길이의 모션그래픽 영상을 만들어줘. 최대한 역동적으로 만들어줘."**
4. 슬라이드에 넣기: "방금 만든 영상을 1페이지와 2페이지 사이에 삽입해줘. 전체화면으로 자동 재생되도록 설정해줘." 또는 마지막 페이지로: "'[테슬라, 가능성을 움직이다]'를 이 마지막 페이지의 제목으로 해줘."
5. 변형: 프롬프트 뒤에 **"쇼츠용으로 만들어줘"**(세로 비율), **"음악은 넣지 말아줘"** 한 줄 추가.

**포인트:** 주제·길이·"최대한 역동적으로" 세 가지면 충분하다. 슬라이드 한쪽에 작게 넣는 것도 가능하다.

**완료 기준:** 만든 영상이 슬라이드 안에서 자동 재생되고, 파일 용량·재생이 발표 환경에서 무리 없다.
**한 줄 정리:** 모션은 **레퍼런스 파일명을 고정**하고, 주제·길이·역동성만 말하면 된다.

## 7. 쓰는 방법 2가지와 팁 (12:07~13:23)

| 방식 | 방법 | 주의 |
| --- | --- | --- |
| **파일** | 폴더의 HTML을 더블클릭해 크롬으로 연다 | **사내 자료·민감 정보는 이쪽 권장** |
| **링크** | 챗지피티: 공유 → 링크 접근 권한 "전체" / 클로드: 공유 → "링크가 있는 모든 사용자" | 링크를 아는 사람은 누구나 열람 |

- 클로드에서 공유 화면이 안 뜨면 **"아티팩트로 결과물을 열어줘"**라고 요청한다.
- **모션이 느리거나 어색하면** "왜 이런지, 어떻게 개선할지" 물어본다. AI가 슬라이드 코드를 분석해 개선안을 준다. (영상이 꼽는 핵심: **원하는 걸 잘 전달하고, 다르게 나오면 무엇이 문제인지 물어보며 고치는 것**)
- **GPT vs Claude:** HTML 슬라이드는 **챗지피티**가, 모션그래픽 영상은 **클로드**가 더 잘 만드는 경우가 많았다. 주제·효과·모델 버전에 따라 달라진다. 서로 만든 결과물을 섞어 쓸 수 있다(클로드 모션 → 챗지피티 슬라이드, 그 반대도).

**한 줄 정리:** 배포는 파일이 기본, 링크는 공개해도 되는 자료만.

## 5-A. 영상 원본 마스터 프롬프트 (설명란·고정 댓글 원문)

> ※ 챗지피티는 맨 앞에 `@Sites`를 붙여 주세요. 클로드는 그대로 쓰시면 됩니다.

```text
폴더에 있는 자료를 기반으로 [주제] 슬라이드를 만들어줘. 디자인은 폴더 안에 있는 '디자인 레퍼런스'를 활용하고, 분량은 [7장] 내외로 만들어줘. 폰트는 [눈누 폰트 주소] 이걸 사용하고, 줄바꿈은 단어 단위로 해서 단어가 중간에서 끊기지 않게 해줘. 마우스를 대면 움직이는 반응형 슬라이드를 HTML로 만들고, 내용 이해를 돕는 이미지도 직접 만들어서 넣어줘. 수치가 들어가는 장은 https://www.chartjs.org/docs/latest/samples/information.html 에서 데이터에 맞는 차트를 골라 넣어줘. 효과나 이펙트는 https://seoul-one-day-many-stories.pegeechmco.chatgpt.site/ 여기를 참고해줘.
```

**원문의 구조를 뜯어보면 6개 지시뿐이다:** ①자료 기반 ②디자인 레퍼런스 ③분량 ④폰트 ⑤단어 단위 줄바꿈 ⑥반응형 HTML + 차트 + 이펙트 레퍼런스. 이 6개가 결과의 뼈대이므로, 아래 강화판에서도 이 여섯은 빠뜨리지 않는다.

## 5-B. 강화판 — 발표 목적까지 넣은 구조화 프롬프트 (내가 확장)

영상 원문은 "무엇을 만들지"만 말한다. 실제 업무 발표에서 결과가 어긋나는 이유는 대부분 **청중·목적·스토리라인이 빠져서**다. 아래는 그 여섯 지시를 유지하면서 요청받은 항목(역할/목표, 청중·맥락, 아웃라인, 레이아웃·시각화 규칙, 데이터·차트, 톤/제약)을 채운 판본이다. `[ ]`만 바꿔 쓴다.

```text
너는 10년 차 프레젠테이션 디자이너이자 프런트엔드 엔지니어다.
폴더의 자료를 근거로, 아래 조건에 맞는 HTML 슬라이드를 단일 파일로 만들어줘.
(챗지피티를 쓸 경우 맨 앞에 @Sites 를 붙인다.)

[1] 목표
- 주제: [예: 2027년 물류 자동화 투자 제안]
- 이 발표가 끝났을 때 의사결정자가 하길 바라는 단 하나의 행동: [예: 1단계 3억 예산 승인]
- 발표 시간: [15분] / 질의응답: [있음]

[2] 청중과 맥락
- 청중: [예: 운영본부장과 재무팀 3명, 물류 자동화 지식 없음, 작년 실패 사례를 기억함]
- 청중이 이미 아는 것 / 모르는 것 / 반대할 지점: [……]
- 발표 자리: [사내 의사결정 회의] / 자료 노출 범위: [사내 한정]

[3] 스토리라인 (이 순서를 지켜라)
1) 표지  2) 한 문장 결론(요청)  3) 현재 상황과 비용  4) 원인 3가지
5) 제안(무엇을, 얼마에, 언제까지)  6) 근거 수치  7) 리스크와 대응
8) 실행 로드맵  9) 요청 사항(CTA)
- 각 장은 "결론형 헤드라인 1문장 + 근거 1개 + 시각자료 1개"로만 구성한다.
- 분량은 [8장] 내외, 헤드라인은 [20자] 이내, 장당 본문은 40단어 이하.
- 슬라이드에 없는 내용은 발표자 노트(스피커 노트)에 장당 3줄로 적는다.

[4] 레이아웃·시각화 규칙
- 16:9(1280×720) 기준, 12컬럼 그리드, 사방 여백 최소 64px, 요소는 그리드에 맞춘다.
- 위계: 헤드라인 44px / 소제목 28px / 본문 18px / 캡션 14px. 폰트는 최대 2종.
- 폰트: [눈누 폰트 페이지 URL] — CDN으로 불러오고 실패 시 폴백 스택을 지정한다.
- 색: 주색 1 + 보조색 2 + 회색 3단계. 본문 텍스트 대비는 4.5:1 이상.
- 장표 유형은 5종만 쓴다: 표지 / 한 문장 주장 / 수치 카드 / 차트 / 다이어그램. 같은 유형을 3장 연속 쓰지 않는다.
- 줄바꿈은 단어(어절) 단위로 하고, 한 줄에 한 단어만 남는 고아 줄을 만들지 않는다.
- 디자인 감각은 폴더의 '디자인 레퍼런스'를 따르되, 색·폰트는 위 규칙을 우선한다.

[5] 데이터·차트·다이어그램
- 수치 장표는 https://www.chartjs.org/docs/latest/samples/information.html 에서 목적에 맞는 차트를 고른다(추세=line, 항목 비교=bar, 구성비=stacked bar, 상관=scatter).
- 모든 차트에 축 이름·단위·출처·기준연도를 표기하고, 색은 3색 이내, 범례는 필요할 때만.
- 프로세스·구조·비교는 텍스트 나열 대신 인라인 SVG 다이어그램으로 그린다. 화살표는 방향과 순서를 실제로 표현해야 한다.
- 자료에 없는 수치는 절대 만들지 않는다. 필요한데 없으면 [확인 필요: ○○] 로 표시하고 목록으로 따로 보고한다.
- 단위·통화·연도를 문서 전체에서 통일한다.

[6] 톤과 문장
- [간결한 보고체] / 전문용어는 첫 등장 시 한 줄로 풀어 쓴다.
- 감탄·수식어 금지. 숫자와 사실로 말한다.
- 존댓말 슬라이드 문구, 발표 노트는 구어체.

[7] 상호작용(필요한 것만)
- 호버 시 수치 카운트업·그래프 채우기 / 세로 레버로 사양 비교 / 연도 클릭 시 지표 연동
- 항목 클릭 시 아래에서 사이드바 상세(배경은 어둡게, 블러 없음)
- 클릭·엔터로 요소 순차 등장, '발표 시작' 버튼으로 자동 진행
- 키보드 ←/→·Space 진행, ESC로 전체 장표 개요, 발표자 모드(현재/다음 장)

[8] 기술 제약
- 단일 HTML 파일. 외부 의존은 폰트 CDN과 chart.js CDN만. CDN이 막히면 시스템 폰트로, 차트는 표로 폴백한다.
- @media print 로 장당 1페이지 인쇄가 되게 한다.
- 1280×720과 세로 모바일(390px)에서 레이아웃이 깨지지 않게 한다(모바일은 세로 스크롤 허용).

[9] 진행 방식
- 먼저 아웃라인 표(장 번호 | 헤드라인 | 근거 | 시각자료 | 발표 노트 1줄)를 보여줘. 내가 승인하면 HTML을 생성해.
- 생성 후 자체 점검 결과를 표로 보고해: 폰트 로드 / 텍스트 오버플로 / 대비 / 링크 / 키보드 진행 / 인쇄.
```

**이 판본을 쓰는 요령**
- 1·2번(목표·청중)을 비워 두면 AI는 "일반적인 소개 자료"를 만든다. 이 두 칸이 결과를 가장 크게 바꾼다.
- 9번(아웃라인 먼저)을 빼면 스토리가 아니라 장표 묶음이 나온다. 초안에서 아웃라인을 고치는 게 HTML을 고치는 것보다 싸다.
- "자료에 없는 수치는 만들지 않는다"는 문장은 빼지 않는다. 영상 원문에는 없지만, 발표자료에서 지어낸 수치는 되돌릴 수 없는 사고다.

## 5-C. 영상의 수정 프롬프트 15종 (원문, 페이지 번호만 바꿔 쓰기)

```text
[내용 수정]
1. 전체 텍스트를 지금보다 조금 더 키워줘.
```

## 5-E. 실제 `.pptx` 파일이 필요할 때 (영상에 없는 내 확장)

영상은 HTML 슬라이드를 만들고, **PPT 변환은 권하지 않는다.** 댓글에서도 HTML→PPT 변환은 "정상 동작이 잘 안 된다"는 실사용 후기가 있고([@ko9ma](https://www.youtube.com/watch?v=byShnblO4Oc&lc=Ugxcn1d-4d0sN7xGsb14AaABAg), 좋아요 16), 공공·사내 규정상 PPT가 필요한 경우는 영상도 인정한다. 그럴 때는 **HTML을 억지로 변환하지 말고, 같은 아웃라인을 PPT 스펙으로 다시 뽑는 것**이 안전하다.

```text
앞서 만든 아웃라인을 그대로 유지해서, PowerPoint에서 손으로 옮길 수 있는 "장표 스펙 표"로 바꿔줘.
컬럼: 장 번호 | 레이아웃 유형(표지/한 문장/수치 카드/차트/다이어그램/표) | 헤드라인 | 본문 불릿(각 15자 이내, 최대 3개)
| 넣을 시각자료(차트 종류·축·단위·데이터 값) | 강조 색 | 배치 좌표(제목/본문/시각자료 영역을 12컬럼 기준으로) | 발표 노트
조건: 폰트는 [맑은 고딕/회사 지정], 색은 [주색 HEX], 16:9. 애니메이션은 '클릭 시 순차 등장'만 쓰고, 차트는 PPT 기본 차트로 재현 가능한 종류만 고른다.
```

필요하면 같은 스펙으로 `python-pptx` 스크립트를 생성하게 할 수도 있다. 다만 이 경우 폰트·레이아웃·차트 스타일은 HTML만큼 자유롭지 않으므로, **정적 배포본은 PPT, 발표·상담용은 HTML**로 나눠 쓰는 편이 현실적이다.

## 실무 인사이트 / 한계 / 추천 대상

**실무에 바로 옮길 것**
1. **"폴더 = 컨텍스트"** — 자료·디자인 레퍼런스·출력물을 한 폴더에 두고 파일명을 고정한다. 프롬프트에서 파일명으로 지목할 수 있어 결과가 예측 가능해진다.
2. **아웃라인을 먼저 승인받는다** — HTML을 고치는 것보다 아웃라인을 고치는 게 싸다. 강화판 프롬프트의 9번이 이 역할이다.
3. **"페이지 · 트리거 · 결과" 3요소 지시** — 효과가 어긋나는 원인은 거의 이 셋 중 하나가 빠진 것이다.
4. **편집 모드는 켜고 반드시 끈다** — 안 끄면 발표 중 텍스트가 바뀐다. 저장 후 해제 프롬프트를 세트로 쓴다.
5. **민감 자료는 링크 공유 금지, HTML 파일로** — 링크를 아는 사람은 누구나 연다.

**한계**
- 공공기관·일부 기업은 PDF/PPT만 접수한다. 제출 요건은 도구보다 먼저 확인한다.
- 챗지피티/클로드 **데스크톱 앱의 유료 플랜과 폴더 연결·플러그인 기능**이 전제다. 무료 플랜에서는 이 워크플로가 그대로 되지 않을 수 있다(영상은 이 부분을 다루지 않는다).
- HTML→PPT 변환은 신뢰할 수 없다(댓글 실사용 후기). PPT가 필요하면 아웃라인을 다시 뽑는 쪽이 안전하다.
- 모션그래픽은 코드로 만든 영상이라 **파일 크기·재생 성능**이 발표 노트북에 따라 문제가 될 수 있다. 리허설 때 실제 발표 장비에서 재생해 본다.
- 영상이 제시하는 모델명·UI 위치는 2026-10 시점이다. 모델·메뉴는 바뀐다.

**추천 대상:** 견적 상담·제안서·투자 설명처럼 **같은 자료로 조건만 바꿔 여러 번 보여줘야 하는** 발표를 하는 사람. 반대로 제출용 문서나 규정 양식이 정해진 자리에는 PPT가 낫다.
